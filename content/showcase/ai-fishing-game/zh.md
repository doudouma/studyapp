## 它是什么

AI Fishing Game 是开发者 u/RUSuper 的个人游戏开发实验，目标是在 Godot 中完全借助 AI 做出一个完整的低多边形钓鱼与航海游戏。项目历时数周，使用 Claude（主要在 Max 套餐上运行 Ultracode）配合 ChatGPT，展示了一条端到端的多智能体流水线：从 2D 参考美术，到通过模型上下文协议（MCP）在 Blender 中自动生成低多边形 3D 模型，再到集成进 Godot 4.7.1 的自定义 GLSL 水面着色器。

## 核心价值主张

这套工作流证明：一个人只当「美术总监」，通过编排模块化的 AI 会话，也能产出一致连贯的 3D 游戏环境：

* **脚本化程序建模**：用连接 Blender（经 MCP）的专用 Claude 会话取代原始网格生成工具，确保模型可编辑、低多边形且风格统一。
* **严格的来源追踪**：强制维护一份决策日志，明确标注每个选择是用户指定还是 AI 建议，杜绝「合成想法演变成虚幻需求」的幻觉。
* **盲评视觉分级**：用游戏内相机视角、按预先设定的标准（8/10 阈值）打分，并做盲测对比，以消除新奇感带来的偏见。
* **多会话智能体联邦**：由一个主会话向各专项子会话（建模、集成、着色器、UI）派发独立任务，并管理它们之间的交接。

## 它可能替代谁

| 目标软件 | 可行性 | 结论与适用场景 |
| --- | --- | --- |
| 手工低多边形 3D 建模 | 中等 | Claude 经 Blender MCP 能很好地脚本化简单道具、码头与船只；复杂带骨角色仍需专业工具。 |
| 传统着色器编写 | 高 | Claude 能可靠地在 Godot 中直接做出复杂水面着色器、波浪动态与昼夜色彩过渡。 |
| 生成式 3D 网格平台（如 Rodin） | 高 | 脚本化产出的低多边形资产比直接生成式网格拓扑更干净、文件更小。 |
| 人工 UI 草图流程 | 中等 | 能快速起草主题化背包界面与航海图鉴，但空间细节仍必须人工打磨。 |

## 当前现实与局限

* **Token 消耗与速率限制严重**：深度迭代会在几天内就触及 Claude $200/月套餐的上限，需要回退到 Codex 等次级模型作为桥梁。
* **环境穿模与不合理布局**：缺少持续人工把关时，生成式布局会产生不合逻辑的几何体，比如无法进入的封闭码头、嵌进悬崖里的房屋、悬空的 NPC。
* **引擎热降频**：复杂的着色器通道与编辑器模拟会让未优化的移动硬件（如 MacBook）温度飙升并掉帧。
* **游戏深度不足**：虽然环境漫游与程序化水面着色器远看很精致，但任务机制与成长系统仍只是骨架级的占位。

## 开发历程与迭代闭环

工作流从基础的提示词输入，逐步演进为由一个总导演会话统辖的模块化多会话流水线。

| 阶段 | 使用的模型 / 工具 | 重点 |
| --- | --- | --- |
| 2D 参考与 UI 草图 | ChatGPT / Playground | 港口结构、鱼类图鉴与改装界面的概念图生成 |
| 3D 几何生成 | Claude（Ultracode）+ Blender MCP | 脚本化创建低多边形船只、建筑与道具 |
| 集成与着色器 | Claude Code + Godot MCP | 水面渲染、昼夜循环、比例匹配与海岸线摆放 |
| 打磨与溢出编码 | OpenAI Codex | 在每周 Claude 速率限制冷却期间修 bug、清理脚本 |

## 社区反响与关键争议

该帖引起独立开发者的广泛关注，同时也凸显出 AI 游戏开发反复出现的张力：

* **氛围获赞 vs. 逻辑崩坏**：评论者高度称赞其*《渔帆暗涌》*式的氛围视觉，但资深设计师很快指出破坏沉浸感的不一致，比如被封死的楼梯与过于拥挤的建筑摆放。
* **「决策日志」获认可**：同行开发者普遍称赞记录「想法来自用户还是模型」的做法，认为这是防止 AI 提示词蔓延的关键卫生习惯。
* **创作即娱乐**：社区成员争论，个人 AI 游戏开发究竟在商业上可行，还是更像一种全新的、极具吸引力的、类似拼乐高的创作爱好。
