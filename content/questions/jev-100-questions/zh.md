## 写在前面

这是一套「100 个问题」主题文档：用问题把一个主题拆开，再一个问题一个问题地读透。

Jev 代表的是一类新模型：不生成自由文本，而是把判断压缩成一次函数调用，返回类型化答案和校准概率。它便宜、快、输出确定，但边界也很清楚：它不擅长生成、解释、计数、算术和多跳推理。这份文档按 6 个阶段展开：先理解它是什么，再接入、拆问题、避坑、做校准，最后判断该用在哪儿、不该用在哪儿。

**快速回答**

- 把 Jev 当成「判断层」，不要当成通用大模型。
- 任务要可枚举、可验收、可校准；需要生成/解释/长程推理时留给大模型。
- 先跑基线、影子模式和自己的校准集，再小流量切换。
- 阈值跟着业务风险走，高风险动作保留人工复核和回滚。
- 官方数字和社区评测都要回源核对，别把营销口径当实测。

## 1. 只做选择题的模型

### 1. 为什么 Jev 一个不生成文字的模型敢自称前沿智能？

因为它在 System One 任务上把判断做成类型化输出：读状态、返回选项和校准概率，不生成自由文本。官方限定「前沿」只指这类快速决策任务，不是通用生成或推理。

### 2. System One 这个名字借对了还是蹭错了？

借的是「快速、直觉式判断」这层含义，不是认知科学里的严格定义。它强调低延迟决策，但不要把它理解成具备人类系统一的全部能力。

### 3. 官方说零幻觉为什么社区吵成一团？

零幻觉指的是不生成自由文本、输出被限制在预设选项内，所以不会编造一段话。但选错选项、概率校准不准、对输入理解错，仍然会发生。

### 4. 刚发布就被叫闭嘴模型这外号冤不冤？

不算冤。它只做选择题，不写解释、不和你聊天，输出是一个封闭集合里的答案；想要理由和追问，仍然要接大模型。

### 5. 本科生课后作业水平的嘲讽站得住脚吗？

部分站得住：它的任务范围很窄，很多题靠简单规则或小模型也能做。但它把分类、评分、守门做成统一 API，并带校准概率，工程价值不在「题有多难」。

### 6. 近六万人收藏的宣言推到底许诺了什么？

许诺的是一种新的模型类别：不生成文本、只做可验证判断，速度快、价格低、输出结构确定。它没有许诺通用智能，也没有许诺每个答案都正确。

### 7. 动手前怎么判断自己的管线需不需要 Jev？

看你的任务是不是反复出现的分类、路由、评分或守门，而且答案可以枚举、可以验收。如果任务需要生成、解释或多步推理，先别换。

### 8. 哪些判断该交给 Jev 哪些必须留给大模型？

枚举清楚、边界稳定、可以校准的判断交给 Jev；开放式生成、复杂推理、需要解释和兜底的判断留给大模型。

### 9. 把分类调用换过来一年能省多少钱？

取决于调用量和原模型价格。Jev 只按输入 token 计费、输出免费，常见的分类/路由任务成本会明显下降；但要把重试、兜底和人工复核算进去。

### 10. 上手 Jev 之前要先认清哪几条官方自认的短板？

它不擅长计数、算术、视觉、多跳推理和复杂解释，也不保证单个答案正确。官方缺陷页列出的坑，最好先逐条对照自己的任务。

### 11. 它和传统机器学习分类器是新瓶旧酒吗？

不是同一个东西。传统分类器要标注数据和特征工程；Jev 用自然语言描述状态和选项，靠 RLCD 做校准，接口更像「一次函数调用」。但任务形态确实接近分类。

### 12. 为什么说 RLHF 是自动化迟迟不来的根因？

RLHF 依赖人类偏好标注，成本高、周期长，难以覆盖大量细分判断。Jev 试图用可自动生成的反馈来校准，让「为每个小判断训一个模型」变得更便宜。

### 13. RLCD 跟 RLHF RLVR 到底差在哪一个目标上？

RLHF 对齐人类偏好，RLVR 用可验证奖励做强化学习，RLCD 更强调用可自动构造的对比/校准信号训练判断模型。目标是让概率更可信，而不是让文本更像人。

### 14. 把前沿智能塞进一次函数调用是什么路数？

把「模型能力」包装成一个稳定的 API：输入状态和候选，输出类型化决策和概率。调用方不用管提示词、解析和重试，像调用普通函数一样使用判断能力。

## 2. 五分钟接上第一个决策

### 15. 五分钟跑通第一个 Jev 决策该走哪条路？

注册拿 key，用官方 SDK 发一次最小请求：一个 state、一个问题、几个选项。先看返回结构和概率，再把它接进自己的业务。

### 16. 一次 API 请求的请求体和响应长什么样？

请求里放 state、问题/选项或评分维度；响应返回选中的类型化结果、概率和置信信息。具体字段以官方 SDK 和文档为准。

### 17. Python 和 JS 两套官方 SDK 怎么选？

跟着你的服务端语言走。Python 适合数据/后端脚本，JS/TS 适合 Node 和前端工具链；不要为了 SDK 换技术栈。

### 18. 五条接入通道分别适合什么场景？

大致分为 API、SDK、Claude Code/Agent 集成、一键包/镜像和自建/开源替代。生产优先官方 API/SDK，尝鲜可以用一键包，但要注意来源和安全。

### 19. 国内网络环境怎么接 Jev 最省事？

优先官方支持的接入方式；如果直连不稳定，用合规代理或镜像，但不要把 key 交给不可信的中转。镜像站的稳定性和隐私要自己承担。

### 20. Jev 只按输入 token 计费对你的用法意味着什么？

输出不额外收费，长候选项和长状态会成为主要成本。把 state 压短、选项收敛，比反复重试更省钱。

### 21. Jev 限流每秒 25 万 token 怎么用满不撞墙？

做批量并发和退避重试，监控 429 和 token 速率；不要用无限重试硬撞。把大请求拆成可控的批次。

### 22. 怎么让 Claude Code 直接使唤 Jev？

把 Jev 包装成一个工具/函数或 MCP/CLI，让 Claude Code 在需要分类、路由、评分时调用。先定义好输入输出和失败兜底。

### 23. 从注册到拿到 key 要过几道坎？

注册、验证、创建 key、配置额度和权限。生产环境还要考虑 key 轮换、环境变量和访问日志。

### 24. Jev 的免注册一键包和镜像站能不能碰？

可以用于本地尝鲜，但不要在生产里用来处理敏感数据。来源不明的包和镜像有供应链与隐私风险。

### 25. 默认型号 jev-latest 背后是什么版本策略？

latest 会跟随官方默认版本，方便但可能悄悄变化。生产里最好锁定明确版本，升级前做回归和校准测试。

### 26. SDK 十二天连发五版说明了什么？

产品还在快速迭代，接口和行为可能变。不要把早期版本当成稳定基础设施，升级要留测试和回滚。

### 27. 第一批请求发出去该先记下哪些数？

延迟、输入 token、成本、返回概率分布、错误率和人工复核结果。没有这些基线，后面无法判断换模型是否值得。

### 28. 三类问题塞进一次调用是营销还是真省？

如果三类问题共享同一段状态和候选，合并调用确实省 token 和往返；如果只是把不相关的问题硬塞，解析和错误处理会更贵。

## 3. 把判断拆成原子问题

### 29. Jev 的 Choice Score Noul 三原语怎么选？

Choice 用于从枚举选项里选一个；Score 用于给一个对象打分；Noul 用于判断某个条件是否成立/是否为空。按任务形态选，不要用一种原语硬套所有问题。

### 30. 喂给 Jev 的 state 该用字符串还是对象？

能用结构化对象就用对象，字段清晰、可复用；只有自然语言上下文才用字符串。无论哪种，都要把无关信息删掉。

### 31. 复合判断怎么拆成 Jev 能接的原子问题？

先拆成互相独立、可枚举的子判断，再决定哪些并行、哪些串行。每个子问题都要有明确的选项和验收标准。

### 32. 问题选项超过 Jev 的 255 上限怎么办？

先做两段收窄：第一段用粗分类缩小候选，第二段在小候选集里做最终选择。不要把所有候选一次性塞进去。

### 33. Jev Score 的档位描述怎么写才不打摆？

每个档位要有可观察的锚点，例如「明确违规/疑似/无关」，并给出边界例子。描述越模糊，评分越不稳定。

### 34. 什么时候值得给问题加几个示例？

当选项容易混淆、业务口径特殊或团队对档位理解不一致时，加少量高质量示例；示例太多会变成另一种提示词工程。

### 35. Jev 官方四大模式该先学哪一个？

先学最贴近你业务的单一模式，跑通一个真实任务，再看其他模式。不要一开始把四种模式全用上。

### 36. Jev 的投机扇出怎么白拿一把免费判断？

在同一个请求里并行评估多个候选/分支，利用它的并行采样一次拿到多个判断；前提是这些判断共享状态，且你能接受一次调用的成本。

### 37. Jev 的置信度红绿灯阈值怎么跟着风险走？

高风险动作提高阈值并要求人工复核，低风险动作可以放宽。阈值必须用你自己的数据校准，不能照搬别人的数字。

### 38. 复合评分的权重怎么定才不讲人情？

权重来自业务目标和历史数据，不来自拍脑袋。先用简单加权跑基线，再用校准和误差分析调整。

### 39. 检索重排怎么把 top1 从 5% 抬到 18%？

用 Jev 对候选做相关性/质量评分，把分数和原有检索分数融合，再在小候选集里重排。提升来自更好的判断信号，不是魔法。

### 40. 引用核查怎么拦住编造的出处？

把「这段话是否真的支持该结论」做成选择题/评分题，并保留原文片段；没有出处或无法验证的引用直接标为待确认。

### 41. 函数调用的参数怎么映射成选择题？

把参数拆成枚举、类型和必填项，用 Choice 选值、用 Noul 判断是否存在；复杂参数先做结构校验，再让模型判断语义。

### 42. 上千个候选里挑一个怎么两段收窄？

第一段用便宜规则/向量检索缩到几十个，第二段用 Jev 做精细评分或选择。不要一步到位。

### 43. 抽日期为什么让模型只读不算？

日期抽取是定位和归一化，不是算术。让模型从文本里读出日期片段，再用确定性代码解析和校验，避免它心算。

### 44. 同一道题换个问法结果能差出一截？

会。选项措辞、顺序、state 的表述都会影响概率。关键任务要固定问法，做措辞鲁棒性测试。

### 45. 挪威语实测里 Score 是 Jev 唯一赢的题型？

这类实测通常样本有限，只能说明某个语言/任务上的相对表现，不能外推成「Score 全面更强」。要自己在目标语言和数据上复测。

### 46. Jev 官方说无上下文腐蚀又自认有腐蚀？

官方说的是它不生成文本、不累积长对话，所以没有传统 LLM 的上下文腐蚀；但输入本身有噪声、选项有歧义时，判断仍会退化。

### 47. Jev 的 Noul 为什么不配独立置信度？

Noul 更接近布尔/存在性判断，输出空间小，官方没有给它单独的校准概率。需要置信度时，用 Choice/Score 或额外校准。

### 48. 问题编号不发给模型这个设计图什么？

避免模型把编号当成语义线索，减少位置/顺序偏差。编号只在调用方用于映射结果。

## 4. 这些坑官方自己都认

### 49. Jev 官方缺陷页自己列了哪九个坑？

大致包括计数、算术、视觉、多跳推理、对抗文本、跨请求阈值、解释缺失、校准漂移和语言/领域泛化。逐条对照自己的场景。

### 50. 同一张票两个题型给出打架的答案？

Choice 和 Score 的问法不同，模型看到的语义线索也不同。关键任务要统一原语和问法，冲突时以人工复核为准。

### 51. 为什么 Jev 数不清楚东西也算不了算术？

它不执行逐步计算，也不维护计数状态；数字对它更像语义 token 而不是可运算对象。计数/算术交给确定性代码。

### 52. 五子棋怎么十几手就被人杀下神坛？

棋盘状态需要长程搜索和精确计数，Jev 做的是局部判断，不是搜索算法。它适合「这一步好不好」，不适合自己下完整盘棋。

### 53. 宝可梦通关视频为什么被扒出靠地图导航？

演示可能把记忆/地图/脚本和模型判断混在一起，观众以为是模型自己探索。拆开看，很多步骤是工程管线而非单模型能力。

### 54. 四百张涂鸦盲测怎么暴露它看不见？

纯文本模型没有视觉能力，涂鸦盲测会接近随机。多模态任务要接视觉模型，不能指望 Jev。

### 55. Jev 的置信度公式什么时候会骗你？

当输入分布和校准数据不一致、选项边界模糊或对抗文本出现时，概率会过度自信。阈值必须按场景校准。

### 56. 为什么 Jev 的阈值不能跨请求搬？

每个任务的类别分布和风险不同，校准是「模型+数据」的性质。A 任务的 0.8 不等于 B 任务的 0.8。

### 57. 对抗文本为什么还能撬动它的答案？

它仍然读自然语言，精心构造的措辞、否定和诱导会影响判断。高风险场景要做输入清洗、规则护栏和人工复核。

### 58. 中文场景动手前必须先测哪几样？

中文选项措辞、领域术语、否定句、长 state、数字/单位、以及和你业务分布一致的校准集。英文表现不能直接外推。

### 59. 双重否定和多跳推理为什么容易翻？

它擅长单步、封闭选项的判断；双重否定和多跳需要组合推理，超出 System One 的强项。拆成多个单步问题或交给大模型。

### 60. 零类型错误和答对了是同一件事吗？

不是。零类型错误只保证输出符合 schema，不保证语义正确。类型正确、答案错误仍然会发生。

### 61. Jev 答错了不给理由为什么可能是硬伤？

因为它只给结果和概率，不解释「为什么」。调试、审计和向用户解释时，需要额外的日志、规则或大模型兜底。

### 62. 公开榜分高密封榜拉胯说明什么？

说明公开榜可能过拟合或分布不同。上线前要用自己的密封集/影子流量验证，不要只看榜单。

### 63. 概率加起来等于一为什么不等于靠谱？

概率归一化只是数学约束，不代表校准正确。模型可能把 0.9 给错答案，关键是校准误差和业务阈值。

### 64. 中文教程里的转引数字为什么必须回源核对？

二手教程可能转错、过期或断章取义。价格、延迟、准确率这类数字要回到官方文档或原始评测。

## 5. 先验校准再谈上线

### 65. F1 更高的模型为什么可能更没用？

F1 是单一阈值下的综合指标；业务可能更在意高精度、低误杀或校准。F1 高但概率不可信，决策仍然难用。

### 66. ECE 和 Brier 两个数怎么算怎么看？

ECE 衡量预测概率与真实频率的分档偏差，Brier 是概率预测的均方误差。两者都要在业务分布上算，不能只看一个。

### 67. 为什么必须先跑 GBT 基线再谈换模型？

梯度提升树在表格/结构化任务上很强，先有基线才知道 Jev 的增量价值。没有基线，换模型只是换感觉。

### 68. 影子模式要怎么跑才算数？

让 Jev 在后台对真实流量做判断，不影响线上结果；记录它和大模型/人工的差异、成本和延迟，再决定是否切换。

### 69. 在自己的数据上验校准具体验什么？

分档可靠性、ECE/Brier、阈值处的 precision/recall、以及不同子群体上的偏差。不要只用整体准确率。

### 70. 实验结果怎么判是能力还是便利？

看增益是否来自判断质量，而不是接口更短、部署更简单。能力提升要能在盲测/密封集上复现。

### 71. 样本要多少条结论才站得住？

取决于类别数和误差容忍度；稀有类别需要更多样本。至少要让每个关键档位有足够正负例，并做置信区间。

### 72. 阈值定多高该跟着什么走？

跟着误判成本和人工复核能力走。高风险动作宁可多转人工，低风险动作可以放宽。

### 73. 上线之后怎么一键退回大模型兜底？

保留开关和双写日志，Jev 超时/低置信/异常时自动转大模型或人工；确保回退不改变上游契约。

### 74. 措辞越严谨校准反而越差是真的吗？

有可能。过于法律化/冗长的选项会偏离模型训练分布，反而降低判断稳定性。用业务自然语言并在自己的数据上测。

### 75. 官方评测的参考答案为什么被揪住不放？

如果参考答案本身有歧义或错误，评测分数就不可信。社区会复现、抽查和质疑标注口径。

### 76. 当裁判方差低九百倍是怎么测出来的？

这是评测方法层面的比较：让模型做裁判时，重复评分的方差远低于人类裁判。具体数字要看原始实验设置和样本。

### 77. 一个只会说不合格的常数凭什么也算好分类器？

如果数据极度不平衡，常数分类器在 accuracy/F1 上可能看起来不差，但它没有区分能力。要看 precision/recall、校准和业务成本。

### 78. 每次都答得一样为什么不代表答得对？

确定性只说明输出稳定，不说明判断正确。稳定地错比随机地错更危险，因为你更容易信任它。

### 79. 校准为什么是模型加数据的性质不是模型的？

同一个模型在不同分布、不同选项集上的校准会变。阈值和概率必须绑定具体任务和数据。

### 80. 多问几遍取平均能不能当校准用？

可以降低方差，但不能自动修正系统性偏差。集成/多次采样是工程手段，不是校准的替代品。

## 6. 用在哪儿别用在哪儿

### 81. 内容审核的双向护栏怎么用它搭？

一边用 Jev 做高风险内容的快速拦截/分流，一边保留大模型或人工复核；双向指误杀和漏放都要有回退。

### 82. 客服工单怎么按意图分流到合适处理器？

把意图做成枚举，用 Choice 分类，低置信度转人工；再用 Score 排优先级。先跑影子模式验证分流准确率。

### 83. Agent 的危险动作怎么加一道执行前闸门？

在执行删除/付款/外发前，用 Jev 对动作和上下文做风险判断；高风险必须人工确认，低风险放行。

### 84. 结构化抽取怎么做到一个字符都不错？

让模型只做定位/分类，具体字符串用确定性解析器抽取和校验；不要让它自由生成关键字段。

### 85. 上下文压缩怎么只删对话里的废料？

把每段对话做成「保留/删除/待确认」的分类题，保留决策、事实和约束；压缩后再让大模型复核。

### 86. 数据库查询里能直接写语义条件吗？

可以把自然语言条件转成结构化过滤器/枚举，但不要让它直接生成 SQL 执行。语义判断和数据库操作要分开。

### 87. 浏览器自动化换 Jev 导航能快多少？

如果页面元素和动作可以枚举，Jev 可以快速选下一步；但页面变化、视觉定位和异常处理仍然需要浏览器工具兜底。

### 88. 开源平替五大家各占哪个山头？

常见的有本地小模型、嵌入/重排模型、传统分类器、规则引擎和 LLM 路由框架。各自擅长不同环节，不是同一个东西。

### 89. 什么预算和团队条件下该自己训一个？

有稳定数据、明确标签、持续迭代需求和 ML 工程能力时再自训；否则先用 API 或开源模型验证价值。

### 90. 用开源平替等于免费吗锅谁背？

不是。模型免费但部署、标注、调优、监控和事故责任都要自己承担。省的是授权费，不是总成本。

### 91. 哪些信号说明你的管线根本不适合 Jev？

任务需要生成/解释、长程推理、视觉、精确计数，或者选项无法枚举、验收标准说不清。这些场景先别换。

### 92. 193 点 6 倍快 444 倍便宜的数字怎么来的？

这些是厂商/评测在特定任务、特定基线下的对比数字，不是通用承诺。要核对任务、硬件、模型版本和计费口径。

### 93. 快 25 倍的神话是怎么被戳破的？

社区复现发现对比基线、缓存、批处理或任务难度不一致，真实端到端差距没有宣传的那么大。看 benchmark 要看出处和设置。

### 94. 复刻党两天三千星围追堵截说明什么？

说明这个方向有真实需求，也说明护城河不在「想法」本身。复刻很快，难的是数据、校准和工程化。

### 95. OpenAI 们会不会一口把它吞了？

大厂可能把类似能力并入现有模型/API，但专用判断模型在成本、延迟和确定性上仍有空间。关键看它能否持续积累数据和场景。

### 96. 它的护城河是架构秘密还是数据工厂？

更可能是数据工厂：持续生成高质量对比/校准数据、覆盖长尾场景、把工程管线打磨到稳定。单点架构容易被复刻。

### 97. 计算机操作框架两万七千星跟它有什么关系？

Agent/计算机操作框架是需求侧：它们需要便宜、快速、可校验的判断层。Jev 这类模型可以成为其中的一个组件。

### 98. 五年 TFP 年增 3% 的豪言该怎么核对？

看 TFP 的定义、统计口径、样本期和来源。宏观增长预测不是产品能力证明，别把愿景当实测。

### 99. 决策模型会是下一个被遗忘的分类器吗？

有可能。如果它不能持续证明在真实业务里的增量价值，就会像很多分类器一样变成基础设施里的一个普通组件。

### 100. 真要上 Jev 头一个月该按什么顺序做？

先选一个高频、可枚举、可验收的判断任务；跑 GBT/大模型基线；影子模式验证校准和成本；小流量切换；保留兜底和回滚；再扩到第二个任务。
